# Voice Tool

Голосовой ввод и расшифровка записей для Windows. Всё считается **на вашем компьютере**:
аудио никуда не отправляется, интернет нужен один раз — скачать модели.

Две задачи, которые решает программа:

1. **Голосовой ввод в любое приложение.** Курсор стоит в поле ввода Telegram, браузера,
   Word или VS Code. Вы говорите «Алиса», затем фразу — распознанный текст сам появляется
   в этом поле, в позиции курсора. Enter при этом **не** нажимается: отправлять или нет,
   решаете вы.
2. **Расшифровка аудио и видео.** Перетащили `lecture.mp4` в окно — получили текст,
   а для иностранной речи ещё и перевод на русский. Можно сохранить TXT, SRT или VTT.

Счётчик слов считает **только живой голосовой режим**. Текст из файлов в него не попадает.

## Установка

### Вариант 1: готовый EXE (обычный путь)

Возьмите папку `VoiceTool` из опубликованного build/release-артефакта либо сначала
соберите её по инструкции ниже. Скопируйте полученную `dist\VoiceTool\` куда угодно —
например в `C:\Program Files\VoiceTool`
или на флешку — и запустите `VoiceTool.exe`. Python устанавливать не нужно.

```
dist\
└── VoiceTool\
    ├── VoiceTool.exe        ← запускать это
    └── _internal\           ← библиотеки, трогать не нужно
```

При первом распознавании скачается модель Whisper (`small` ≈ 465 МБ) — один раз, дальше
всё работает офлайн. Скачать её заранее можно на вкладке **Проверка** кнопкой
«Скачать модель распознавания».

Обновление: замените папку `VoiceTool` новой. Статистика, история и настройки лежат
отдельно (`%APPDATA%\VoiceTool`) и не пострадают.

Собранные `VoiceTool.exe` и `_internal` — генерируемые файлы, в source tree они не
хранятся. Актуальную папку всегда создают `VoiceTool.spec` и `build_exe.py` в `dist`.

### Вариант 2: из исходников

Нужен Python 3.9+ (проверено на 3.11).

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python VoiceTool.py
```

`ffmpeg` **не требуется**: звук из видео достаёт библиотека `av`, которая ставится вместе
с `faster-whisper`. Он нужен только как запасной декодер для экзотических контейнеров —
если такой попадётся, программа скажет об этом сама.

## Запуск

| Что нужно | Как |
|---|---|
| Открыть окно | `VoiceTool.exe` |
| Свернуть в трей сразу (автозапуск) | `VoiceTool.exe --tray` |
| Сразу начать слушать | `VoiceTool.exe --listen` |
| Обработать файл | `VoiceTool.exe lecture.mp4` |
| Демонстрация без микрофона | `VoiceTool.exe --source samples\ru_live.wav --listen` |

Второй запуск не создаёт второе окно — программа показывает уже работающее.

## Голосовой ввод (главная функция)

1. Включите прослушивание — кнопкой в окне или из меню трея.
2. Поставьте курсор в текстовое поле любого приложения (Telegram, Discord, браузер,
   Notepad, Word, VS Code, ChatGPT…).
3. Скажите **«Алиса»** — в левом верхнем углу появится кружок-индикатор.
4. Скажите фразу и сделайте паузу (по умолчанию 2.5 секунды).
5. Текст появится прямо в поле ввода, в позиции курсора.

Можно и одной фразой: «Алиса, напомни мне купить молоко» — всё после слова-триггера
считается командой.

### Как именно набирается текст

Символы отправляются в приложение по одному через `SendInput` с флагом
`KEYEVENTF_UNICODE`. Это не эмуляция нажатий клавиш: в событие кладётся сам код символа
UTF-16, а код клавиши остаётся нулевым. Windows отдаёт приложению готовый символ мимо
раскладки — поэтому одинаково проходят русский, английский, эмодзи, знаки препинания
и переносы строк, независимо от того, какая раскладка включена и есть ли вообще такая
клавиша на клавиатуре.

**Буфер обмена не используется вообще** — ни как основной путь, ни как запасной.
Он не читается и не изменяется: в тесте за ним следят в момент набора и сверяют
счётчик `GetClipboardSequenceNumber`, который Windows увеличивает при любой записи.

Переносы строк отправляются как `Shift+Enter`: он переводит строку и в Блокноте,
и в поле браузера, но, в отличие от голого `Enter`, не отправляет сообщение в мессенджере.

**Темп набора.** Между символами выдерживается пауза 15 мс — это порог, который держат
даже медленные поля (Блокнот Windows 11 нарисован на XAML и при более быстрой отправке
теряет символы, а по отставшим событиям включается автоповтор). Классические поля
принимают и на порядок быстрее, поэтому пауза настраивается: **Настройки → Пауза между
символами**. Фраза в 35 символов набирается примерно за полсекунды.

Если Windows не пропустит ввод (обычно так бывает с приложениями, запущенными от имени
администратора), программа скажет об этом прямо и предложит запустить её с теми же
правами — молча подсовывать текст через буфер она не станет.

### Существующий текст не стирается

Было в поле `Привет,`, вы сказали «Алиса, как дела?» — станет `Привет, как дела?`.
Вставка идёт в позицию курсора, содержимое поля не перезаписывается.

### Если во время распознавания вы ушли в другое окно

Программа запоминает окно в момент срабатывания «Алисы» и после распознавания возвращает
в него фокус. Так предсказуемее: текст попадает туда, куда вы его говорили, а не в то
окно, которое случайно оказалось активным через три секунды.

Поведение отключается: **Настройки → Вставлять результат в приложение, активное при
активации «Алиса»**. Если снять галочку, текст пойдёт в то поле, которое активно
на момент окончания распознавания.

### Enter не нажимается

По умолчанию **выключено**. Сообщение не отправится само — вы решаете сами.
Включается в настройках: «Автоматически нажимать Enter после распознавания».

### Режимы вывода

**Настройки → Куда попадает распознанный текст:**

- **Вставлять в активное приложение** — по умолчанию;
- **Вставлять + показывать в Voice Tool**;
- **Только показывать в Voice Tool** — ничего никуда не вводится.

## Плавающий индикатор

Маленькое окно в левом верхнем углу экрана. Оно **поверх всех окон**, но не забирает
фокус и не перехватывает мышь — сквозь него можно кликать. Главное окно для работы
открывать не нужно.

| Состояние | Что видно |
|---|---|
| Ожидание | небольшая спокойная точка |
| Услышал «Алиса» | круг плавно вырастает |
| Идёт запись | круг пульсирует, вокруг расходятся волны |
| Распознаю | круг с вращающейся дугой |
| Готово | карточка с текстом и «+N слов», через 4 секунды исчезает |

Отключается: **Настройки → Показывать голосовой индикатор поверх окон**.

## Работа в фоне и трей

Закрытие окна крестиком по умолчанию **сворачивает в трей**, а не завершает программу —
прослушивание продолжается. Поведение меняется настройкой «При закрытии окна сворачивать
в трей».

Меню значка в трее: открыть окно · включить/отключить микрофон · пауза · обработать файл ·
статистика · история · настройки · выход.

**Автозапуск с Windows** включается в настройках (по умолчанию выключен). Программа
стартует свёрнутой в трей и сразу готова слушать. Технически это ключ в
`HKCU\Software\Microsoft\Windows\CurrentVersion\Run` — права администратора не нужны.

## Горячая клавиша

`Ctrl + Alt + A` — активировать голосовой ввод вручную, не произнося «Алиса».
Работает из любого приложения. Меняется в настройках; модификатор (Ctrl/Alt/Shift/Win)
обязателен. Если сочетание занято другой программой, об этом будет написано в боковой
панели.

## Видеокарта (CUDA)

Распознавание на видеокарте примерно в десять раз быстрее, чем на процессоре: фраза
разбирается за 0.2 секунды вместо 1.9. Программа включает GPU сама, если находит нужные
библиотеки, и так же сама молча уходит на процессор, если их нет, — на компьютере без
NVIDIA она просто работает, ничего не требуя.

### Что нужно

Видеокарта NVIDIA и две библиотеки: **cuBLAS для CUDA 12** и **cuDNN 9**. Драйвера
недостаточно: он может рапортовать «CUDA 13.2», а самих библиотек в системе не быть —
тогда в логе появляется `Library cublas64_12.dll is not found or cannot be loaded`.

### Как включить

Из исходников:

```bash
pip install -r requirements-gpu.txt
```

Для собранного `VoiceTool.exe` (библиотеки весят около 2 ГБ и в сборку не кладутся —
иначе она распухла бы в семь раз ради тех, у кого нет NVIDIA):

```bash
python tools/install_cuda.py --for-exe
```

Скрипт положит их в `%APPDATA%\VoiceTool\cuda\`, где программа их и найдёт.
Годятся и другие места: установленный CUDA Toolkit (`CUDA_PATH`), папка `cuda` рядом
с `VoiceTool.exe`.

### Как проверить

Вкладка **Проверка**, строка **Бэкенд**:

```
[v] Бэкенд   NVIDIA GeForce RTX 3080 — распознавание идёт на видеокарте
```

Если видеокарта есть, но библиотек нет, там будет прямо сказано, чего не хватает
и какой командой это чинится. То же самое пишется в лог при каждой загрузке модели:

```
CUDA: библиотеки найдены в C:\...\cuda\cublasin; C:\...\cuda\cudnnin
Модель small готова: бэкенд CUDA (float16)
```

или, если видеокарты нет:

```
Загружаю модель small (запрошено device=auto -> cpu, compute=int8); причина отката:
не найдены библиотеки cublas64_12.dll, cudnn64_9.dll
Модель small готова: бэкенд CPU (int8)
```

### Точность вычислений

`compute_type: auto` (по умолчанию) выбирает `float16` на видеокарте и `int8` на
процессоре. Ставить конкретное значение имеет смысл, только если знаете зачем.

### Какую модель брать

С работающей видеокартой можно позволить себе модель побольше:

| Модель | «Алиса» → текст | Качество |
|---|---|---|
| `small` (по умолчанию) | 0.22 с | хорошее, 465 МБ |
| `medium` | 0.37 с | заметно ровнее на редких словах, 1.5 ГБ |

На процессоре `medium` уже втрое медленнее, поэтому по умолчанию оставлен `small`.
Меняется в **Настройки → Whisper → Модель**.

## Словарь имён и редких слов

Whisper коверкает то, чего почти не встречал: фамилии, названия проектов, термины.
Переобучать модель не нужно — ей можно подсказать список ожидаемых слов.

Файл лежит рядом с остальными данными:

```
%APPDATA%\VoiceToolocabulary.txt
```

Открыть его можно кнопкой **Настройки → Словарь имён и редких слов → Открыть словарь**.
Формат простой: по слову или фразе в строке, строки с `#` — комментарии.

```
# Имена и слова, которые модель распознаёт неправильно
Кузьмина
Анастасия
Гильмутдинов
PySide
ctranslate2
WebVTT
```

Файл перечитывается сам, как только вы его сохранили — перезапускать программу не нужно.
Список уходит в модель как `hotwords` (на старых версиях faster-whisper — как
`initial_prompt`), то есть влияет именно на выбор слов при распознавании.

**Сколько это даёт.** На тестовом наборе из 10 фраз с фамилиями и названиями библиотек
(`tools/test_vocabulary.py`):

```
узнано имён без словаря : 4/11 (36%)
узнано имён со словарём : 9/11 (82%)
```

Например, «Напиши кузьменой» становится «Напиши Кузьминой», «Открой проект на pi-сайт» —
«Открой проект на PySide». На скорость это не влияет: 2.4 с против 2.3 с на тех же
10 фразах.

Длинный список вредит — модель начинает подставлять слова оттуда без повода. Держите
в файле то, что реально путается; больше 200 записей программа не берёт.

## Задержка живого режима

Замеряется скриптом `tools/bench_latency.py`. Числа — с этой машины (RTX 3080):

| Что | Было | Стало |
|---|---|---|
| обнаружение слова «Алиса» | 1.61 с | 0.02 с |
| распознавание фразы | 1.90 с | 0.18 с |
| **«Алиса» → готовый текст** | **3.51 с** | **0.20 с** |
| набор текста в поле (35 символов) | 0.53 с | 0.53 с |
| полный путь до текста в приложении | 4.03 с | 0.72 с |

Из чего сложилось ускорение:

* **слово-триггер ловит отдельная лёгкая модель** (`tiny` вместо `small`) — на нём важна
  скорость, а не точность: слово одно, и сравнивается оно всё равно нечётко;
* **жадный поиск для триггера** (`wake_beam_size: 1`) — перебор лучей ради одного слова
  ничего не даёт, а времени съедает в разы больше;
* **без второго VAD на проходе триггера** — тишину по краям уже отрезал сам захват звука;
* **язык берётся из настроек, а не определяется** — на фрагменте в секунду автоопределение
  ошибается (у нас оно выдавало `en` с уверенностью 0.38 на русской фразе);
* **видеокарта** для распознавания самой фразы.

## Обработка файлов

Перетащите файлы в окно, или **Файлы → Добавить файлы**, или запустите
`VoiceTool.exe запись.mp4`.

**Поддерживаемые форматы**
Аудио: `mp3` `wav` `m4a` `flac` `ogg` `opus` `aac` `wma` `aiff` `alac`
Видео: `mp4` `mkv` `avi` `mov` `webm` `wmv` `flv` `m4v` `mpg` `mpeg` `ts`

Можно добавить сразу несколько — они встанут в очередь и обработаются по одному
(`✓` готово, `◐` в работе, `○` ждёт). Видно прогресс, время (`12:34 / 18:20`)
и определённый язык.

**Длинные файлы.** Запись читается кусками по 5 минут: память не растёт с длиной файла,
и час записи обрабатывается так же спокойно, как десять минут. Граница куска ставится
в самом тихом месте рядом с отметкой — чтобы не разрезать слово пополам. Длину куска
можно менять в настройках.

**Результат.** Кнопки `Копировать`, `TXT`, `SRT`, `VTT`. Субтитры — с временными метками.
Копия расшифровки автоматически сохраняется в `%APPDATA%\VoiceTool\files\`.

**Слова из файлов в счётчик не попадают** — это принципиально. В истории такие записи
помечены как «ФАЙЛ».

## Перевод

Если речь в файле не русская, программа показывает и оригинал, и перевод.

Перевод считается **локально**, движком CTranslate2 (он уже стоит вместе с
faster-whisper). Модели языковых пар берутся из открытого индекса Argos Translate: пара
скачивается один раз (~200 МБ, нужен интернет), дальше текст никуда не отправляется.
Прямых пар мало, поэтому редкие языки идут через английский.

Настройка «Только офлайн» запрещает скачивание: будут работать только уже загруженные пары.

## Статистика и история

**Статистика:** всего слов, сегодня, за 7 дней, фраз, сессий, слов на фразу и столбики
по дням недели. Считается только живой режим.

**История:** последние 200 записей с датой и текстом. Голосовые команды помечены `+N слов`,
расшифровки файлов — тегом «ФАЙЛ». Фильтр «Все / Голос / Файлы», кнопка копирования
у каждой записи.

## Настройки

Все переключатели реально работают.

**Голосовой режим** — слово-триггер и его варианты произношения, пауза после речи,
минимальная длина речи, пауза для слова-триггера, порог начала речи, максимальная длина
команды, выбор микрофона.

**Куда попадает распознанный текст** — режим вывода, ввод в окно активации, Enter,
пауза между символами при наборе.

**Whisper** — модель, отдельная модель для слова-триггера, устройство (авто/процессор/
видеокарта), точность, язык живого режима, длина куска при разборе файла. Под полями
показано, какой бэкенд доступен прямо сейчас.

**Словарь имён и редких слов** — включение подсказок и кнопка открытия `vocabulary.txt`.

**Интерфейс и фон** — автозапуск с Windows, сворачивание в трей, плавающий индикатор,
уведомления, прослушивание при запуске, горячая клавиша.

**Перевод** — переводить иностранную речь, только офлайн, сохранять расшифровки.

Если сохранение расшифровок выключено, новые transcript/history/activity-записи не
создаются. Счётчик хранит только агрегированное количество слов без текста.

Смена модели или параметров микрофона перезапускает прослушивание автоматически.

### Слово-триггер: почему обычный Whisper, а не отдельный детектор

Специализированные офлайн-детекторы (openWakeWord и подобные) поставляются с готовыми
моделями на английские фразы вроде «hey jarvis». Модели на слово «Алиса» среди них нет —
её пришлось бы обучать самостоятельно, а это отдельный проект, лишние зависимости
и худшее качество, чем у Whisper. Поэтому короткие фразы прогоняются через Whisper,
а совпадение ищется нечётко (Whisper слышит «Алиса» и как «Алис», и как «Алиса,»).

Зато сам проход сделан дешёвым: слово-триггер по умолчанию слушает **`tiny`** —
самая маленькая модель, жадный поиск, без второго прохода VAD, с языком из настроек.
На это уходит 0.02 секунды. Саму фразу после «Алисы» разбирает уже основная модель.
Меняется в **Настройки → Whisper → Модель для слова-триггера**.

## Где хранятся данные

```
%APPDATA%\VoiceTool\
├── config.json          настройки (у EXE-версии)
├── vocabulary.txt       словарь имён и редких слов (правится вручную)
├── word_count.json      счётчик слов
├── history.jsonl        история распознавания
├── cuda\                библиотеки для видеокарты (кладёт tools/install_cuda.py)
├── transcripts.log      текстовый лог живого режима
├── files\               сохранённые расшифровки файлов
├── models\translate\    офлайн-модели перевода
└── logs\2026-08-29.log  технические логи (хранятся 30 дней)
```

Обычно это `C:\Users\<Имя>\AppData\Roaming\VoiceTool`. Открыть: **Проверка → Открыть
папку данных**.

**Данные никогда не лежат внутри EXE и рядом с ним** — обновление программы их не трогает.

Модели Whisper лежат в кэше HuggingFace (`C:\Users\<Имя>\.cache\huggingface`) — тоже
в профиле пользователя, тоже переживают обновление. Путь можно поменять ключом
`whisper_models_dir` в `config.json`.

Данные старой CLI-версии из `~/.voice_tool` переносятся автоматически при первом запуске.

**Portable-режим.** Переменная окружения `VOICETOOL_DATA_DIR` перекрывает путь — удобно,
если программа живёт на флешке:

```bat
set VOICETOOL_DATA_DIR=%~dp0data
start VoiceTool.exe
```

При запуске из исходников `config.json` лежит в папке проекта (как в старой версии),
у собранного EXE — в папке данных.

## Командная строка

Всё, что умела CLI-версия, работает по-прежнему:

```bash
python voice_tool.py listen                 # живой режим в консоли
python voice_tool.py listen --insert        # + вставлять текст в активное окно
python voice_tool.py listen --source f.wav  # звук из файла вместо микрофона
python voice_tool.py file lecture.mp4       # расшифровка (+перевод)
python voice_tool.py file f.mp4 --srt out.srt --vtt out.vtt
python voice_tool.py count                  # счётчик слов
python voice_tool.py stats                  # статистика
python voice_tool.py history --limit 20     # история (--kind voice|file)
python voice_tool.py check                  # проверка системы
python voice_tool.py gui                    # открыть интерфейс
```

Добавлено по сравнению со старой версией: `--insert`, `--srt`, `--vtt`, команды
`history` и `gui`. Ничего не удалено.

## Сборка EXE

```bash
pip install pyinstaller
python build_exe.py
```

Результат: `dist\VoiceTool\VoiceTool.exe` (~325 МБ вместе с библиотеками).
Иконка рисуется кодом при сборке — отдельный `.ico` в репозитории не нужен.

Однофайловая версия:

```bash
python build_exe.py --onefile
```

Даёт `dist\VoiceTool-portable.exe` (~124 МБ). Он распаковывает себя во временную папку
при каждом запуске, поэтому стартует заметно дольше (десятки секунд против пары секунд)
и работает как два процесса: загрузчик и само приложение. Папочная сборка остаётся
основной; portable удобен, когда нужен ровно один файл — например, на флешке.

Модели Whisper и перевода в EXE **не кладутся**: они большие и живут в папке пользователя.

## Требования

- **ОС:** Windows 10 или 11 (64-bit). Вставка текста в чужие приложения, трей, автозапуск
  и горячая клавиша — только Windows. Ядро распознавания кроссплатформенное, но GUI
  собирается и проверялся под Windows.
- **Процессор:** любой современный x64. Модель `small` на CPU разбирает запись примерно
  за 2–4× её длительности. Слабый ноутбук — берите `base` или `tiny`.
- **Память:** 4 ГБ достаточно для `small`, 8 ГБ комфортно для `medium`.
- **Диск:** ~350 МБ программа + 465 МБ модель `small` + ~200 МБ на пару языков перевода.
- **Видеокарта:** не обязательна, но с ней распознавание примерно в десять раз быстрее.
  Нужны NVIDIA, cuBLAS для CUDA 12 и cuDNN 9 — см. раздел [Видеокарта (CUDA)](#видеокарта-cuda).
  Без них программа молча считает на процессоре и пишет причину в лог.
- **Микрофон:** любой. Разрешите доступ в Параметрах Windows.

## Приватность и офлайн

- **Аудио и видео никуда не отправляются.** Распознавание и перевод считаются локально.
- **Телеметрии нет.** Аналитики нет. Рекламы нет. Сетевых сервисов нет.
- Интернет нужен ровно в двух случаях, оба — разовые и явные:
  1. скачивание модели Whisper при первом распознавании;
  2. скачивание пары языков для перевода при первом переводе.
- После этого можно отключить сеть — распознавание, вставка текста, статистика и
  субтитры работают полностью офлайн.
- Режим «Только офлайн» в настройках запрещает и загрузку моделей перевода.
- Ваш буфер обмена не используется и не изменяется: текст набирается напрямую
  в поле ввода, посимвольно.

## Логи

`%APPDATA%\VoiceTool\logs\ГГГГ-ММ-ДД.log`, по файлу на день, старше 30 дней удаляются.
В лог пишутся запуск, загрузка модели, подключение микрофона, срабатывания слова-триггера,
обработка файлов и ошибки с полным traceback.

Технический лог ротируется по размеру (5 МБ и две резервные части); transcript/history и
AgentActivity также имеют ограничения по строкам и размеру. При отключённом сохранении
расшифровок диагностический лог не содержит распознанный текст.

В интерфейсе показывается короткое понятное сообщение и кнопка «Открыть лог» —
простыней с traceback пользователь не видит.

## Что не так и как чинить

**Не удалось открыть микрофон**
1. Микрофон подключён? 2. Разрешён доступ в Параметрах → Конфиденциальность → Микрофон?
3. Не занят ли он другим приложением (Zoom, Discord, OBS)?
Проверьте на вкладке **Проверка** — там видно список устройств.

**Не срабатывает «Алиса»**
Проверьте уровень на индикаторе громкости в окне: полоски должны шевелиться, когда вы
говорите. Если нет — понизьте «Порог начала речи» в настройках. Если слово слышится,
но не распознаётся, добавьте вариант в поле «Как его может расслышать Whisper».

**Текст не вставляется**
Курсор должен стоять в текстовом поле. Приложения, запущенные от администратора, не
принимают ввод от обычных программ — запустите Voice Tool так же от администратора.
Ещё вариант — переключить режим вывода на «Только показывать в Voice Tool» и копировать
вручную.

**Текст попадает не в то окно**
Проверьте настройку «Вставлять результат в приложение, активное при активации «Алиса»».
Включена — текст идёт туда, где вы были, когда сказали «Алиса».

**Сообщение отправляется само**
Выключите «Автоматически нажимать Enter после распознавания» (по умолчанию выключено).

**Текст набирается медленно**
Уменьшите «Пауза между символами» в настройках (по умолчанию 15 мс). На классических
полях ввода работает и 2-4 мс; Блокнот Windows 11 при таком темпе начинает терять
символы, поэтому по умолчанию выбран безопасный порог.

**Символы теряются или повторяются («Привет цццццц»)**
Наоборот, увеличьте паузу между символами до 20-25 мс. Это признак того, что
приложение не успевает разбирать поток ввода.

**Медленно распознаёт**
Возьмите модель поменьше (`base`, `tiny`) или точность `int8`. На вкладке **Проверка**
видно, используется ли видеокарта.

**Программа «висит» при первом запуске**
Так было в ранней версии: `faster-whisper` сверяет ревизию модели с HuggingFace при
каждом создании модели, и при залипшем соединении приложение вставало без сообщения.
Сейчас модель сначала открывается строго из локального кэша и в сеть уходит, только
если её там действительно нет; для загрузок выставлены таймауты. Если всё же долго —
смотрите лог, там видно, на каком шаге остановились.

**Модель не скачивается**
Нужен интернет и ~500 МБ свободного места. Скачать вручную: **Проверка → Скачать модель
распознавания**. Если сеть за прокси, задайте `HTTPS_PROXY` в переменных окружения.

**Файл не открывается / «нет звуковой дорожки»**
Экзотический контейнер. Поставьте ffmpeg — программа использует его как запасной декодер:
`winget install Gyan.FFmpeg`.

**Горячая клавиша не работает**
Сочетание занято другой программой — в боковой панели окна будет написано. Выберите другое.

```bash
python test_pipeline.py            # 21 проверка логики, без микрофона и модели, ~1 секунда
python tools/test_gui.py           # 35 проверок: страницы, настройки, D&D, трей, автозапуск,

python tools/test_typing.py        # 8 проверок ввода с точным чтением поля
python tools/test_inject.py        # Блокнот и браузер: кириллица, эмодзи, буфер, Enter
                                   #   (--browser добавляет проверку поля поиска)
python tools/test_gpu_fallback.py  # видеокарта и корректный откат на процессор
python tools/test_vocabulary.py    # точность с словарём и без него
python tools/bench_latency.py before after   # задержка «Алиса» -> текст, до и после
python tools/test_files.py         # очередь, перевод, субтитры, ошибки, длинная запись
python tools/test_live_pipeline.py # звук -> «Алиса» -> счётчик -> текст в Блокноте
```

Перед выпуском Windows-сборки выполните отдельный
[чек-лист runtime-валидации](docs/windows-runtime-validation.md). Linux-тесты проверяют
ядро и abstractions, но не заменяют реальную проверку Win32/UIA/DPI/микрофона.

`test_pipeline.py` и `test_gui.py` быстрые. Остальные требуют модель Whisper и идут минуты;
`test_files.py` с длинной записью — десятки минут (длину можно задать: `test_files.py 6`).

Тесты в `tools/` открывают настоящий Блокнот и работают с настоящим буфером обмена —
запускайте их, когда не мешаете себе работать. Свои окна Блокнота они закрывают сами,
уже открытые вами — не трогают. Данные пишутся во временную папку, ваши счётчик
и настройки не затрагиваются.

## Известные ограничения

- **Вставка текста, трей, автозапуск и горячая клавиша — только Windows.**
  Распознавание, перевод и субтитры работают везде, но интерфейс проверялся под Windows.
- **Набор текста занимает время**: 15 мс на символ, то есть около полусекунды на фразу
  в 35 символов. Это плата за надёжность — приложения на XAML (Блокнот Windows 11)
  при более быстрой отправке теряют символы. Пауза настраивается.
- **Библиотеки CUDA не входят в VoiceTool.exe** (2 ГБ). Без них exe работает на процессоре;
  включаются командой `python tools/install_cuda.py --for-exe`.
- **Приложения с правами администратора** не принимают ввод от обычных программ —
  Voice Tool нужно запускать с теми же правами.
- **Слово-триггер ищется полноценным Whisper**, а не лёгким детектором: на короткие
  фразы уходит заметная доля процессора. Причины — в разделе про слово-триггер.
- **Язык длинного файла определяется по первому куску** и дальше фиксируется. Запись,
  где язык меняется посередине, будет распознана как один язык.
- **Прямых пар перевода мало**, редкие языки идут через английский — качество ниже.
- **Однофайловый EXE стартует медленно** (распаковка во временную папку при каждом
  запуске) и виден в диспетчере задач как два процесса. Выходить из программы нужно
  через меню трея: снятие в диспетчере только процесса-загрузчика оставит приложение
  работать. У папочной сборки этого нет.
